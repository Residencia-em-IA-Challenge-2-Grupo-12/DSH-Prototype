# Integrated synthetic calendar checkpoint spike

`src/foundation/calendar-experiment.mjs` composes three independent spikes: the disposable Calendarpit runner, the snapshot-to-fixture converter and the provider API client. It is not connected to the prototype or SQLite service.

A trusted orchestrator starts an experiment with a synthetic fixture, loopback OAuth redirect and explicit fictional scenario/generator/clock metadata. `syntheticCredentials()` exposes the newly generated local client to a caller implementing the synthetic OAuth flow; never log or persist its return value. `provider()` accepts the resulting synthetic access token, and mutations still require a trusted decision verifier. A checkpoint records a UUID, run ID, immediate parent checkpoint ID, fixed-clock metadata, pinned image, normalized replay fixture, old ETags/revision as observations, conversion limitations and an integrity hash. It deliberately excludes OAuth clients, connections and tokens. Callers must supply synthetic fixture content and non-secret metadata; these fields are not content-classified.

To persist, serialize the returned checkpoint to a private file. Reload it and pass it to `replayCalendarExperiment`: integrity is checked before starting a new simulator with fresh client credentials. The hash detects accidental modification; it is not a signature or authentication. Event IDs and supported semantic content are intended to survive, but Calendarpit regenerates ETags/timestamps and drops OAuth state, prior approvals, calendar-list settings and certain runtime records. Never reuse old approvals or tokens. The lineage is an immediate parent pointer; durable repository, complete ancestry lookup, signed provenance and richer experiment artifacts are future work.

The integration test uses two disposable containers, synthetic OAuth and Google-compatible v3 reads; it saves a checkpoint without secrets and verifies semantic replay, credential isolation and lineage. Enable with `CALENDARPIT_LIVE_TEST=1`; Docker and the pinned image are required. Unit tests use injected fake runner and state responses. Neither test establishes production security or real Google compatibility.
