# Model setup

The demo's deterministic planner and offline tests need no model. DSH uses its own isolated profile in `.runtime/dsh`, with settings and provider credentials managed by DSH or its plugins. The study profile defaults to the Codex route and GPT-6 Luna at the user's request; do not run other models unless the user changes that preference. Never copy credentials into the repository or fixture files.

The requested [dsh-plugin-subscriptions](https://github.com/V1ki/dsh-plugin-subscriptions) package version 0.9.12 can be installed with `npm run install:codex-plugin` (stop DSH first). It was installed in the isolated web profile with install lifecycle scripts disabled. Its UI exposes **Settings → Subscriptions → Codex (ChatGPT) → Log in**. The user must complete the provider authorization and review consent. The plugin stores its own OAuth credential in the isolated DSH profile and calls ChatGPT's Codex endpoints; it is a third-party integration, not an official OpenAI plugin. With the user’s sign-in, a synthetic-only run on 2026-11-06 succeeded through DSH 0.2.2-rc.1 and this plugin using GPT-6 Luna (medium reasoning). DSH displayed 13 seconds and approximately 56.3K tokens, including cached context. The agent used the study MCP tools, recovered from one nonexistent-path attempt, cited the syllabus deadline, drafted a proposal and asked for review. No approval or calendar-write tool was called. The prompt explicitly supplied the simulation date, so this does not prove the model will always prefer it over the host clock; the tools now also return or describe that simulated date. This one run is not a reliability or privacy assessment.

The separately documented [OpenAI Sign in with ChatGPT flow](https://developers.openai.com/siwc/token-sharing-open-source) and [Codex app-server](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server) have their own integration and eligibility requirements. Using app-server may introduce Codex's own agent loop, so record whether a comparison tests a DSH model route or a complete Codex agent.

DSH also supports API-key and OpenAI-compatible self-hosted provider routes through its model settings. Configure a chosen provider and model explicitly; no model name or paid API request is assumed. Run only synthetic data through a live provider and record the model, harness, configuration and usage for comparisons. OpenRouter use is deferred pending the user's decision.
