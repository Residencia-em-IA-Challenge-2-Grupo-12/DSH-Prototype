# Luna subscription route: container isolation findings

**Inspected 2026-11-11; synthetic use only.** The current [managed launcher](../src/foundation/docker-agent.mjs) supports the DeepSeek gateway route. It deliberately rejects other routes. The earlier successful Luna SDK run described in [models.md](models.md) used the host-side DSH profile; it did not prove this isolated lifecycle can use the same login.

The locally installed third-party `dsh-plugin-subscriptions` 0.9.12 implements the Codex provider inside the DSH process. Its source stores subscription sessions under the DSH home, refreshes them through the OpenAI authorization endpoint and sends model traffic to the ChatGPT Codex endpoint. The plugin also contains additional capabilities, so their registration and model routes would need to be audited for the Luna-only restriction. The current packaged agent image neither installs the subscription plugin nor mounts its credentials, and its run network has no external egress. We inspected source and package metadata, not the stored credential values.

Mounting the existing DSH home or subscription credential into the agent, or giving that container unrestricted internet access, would contradict the approved separation of the agent from credentials and network access. Copying a refreshable credential into disposable runs can also complicate refresh and revocation. Do not use those shortcuts to obtain a comparison result.

A candidate to investigate is a trusted, separately isolated Luna provider service holding the persistent plugin login, with a narrowly scoped model-only transport to the disposable DSH agent. It would need to preserve streaming, tool calls, cancellation, model identity and failures while avoiding extra generative routes and silent fallback. Whether the pinned plugin or DSH SDK offers a supported interface for such a split is **not yet established**; a custom bridge may be substantial. First probe the boundary using fake credentials and a scripted upstream, audit the actual tool/model catalog and request destinations, then test the authorized Luna route only after the boundary is verified. Keep the DeepSeek and Luna runs identical apart from model route, and do not represent the existing scripted gateway results as model comparisons.

The installed package contains an internal `CodexAdapter` implementation with a streaming method, but its package export map does not expose that provider module as a public subpath. Reaching into that internal file would couple the bridge to an unsupported implementation detail; this source inspection alone does not rule out another supported integration.

The real DeepSeek gateway is also intentionally unable to make paid calls until trusted current pricing, egress and accounting are wired and tested. No live model comparison or user-facing integration follows automatically from this investigation.
