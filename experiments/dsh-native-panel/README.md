# Native DSH synthetic calendar panel experiment

This read-only experiment packages a proportional week view as a DSH sidebar plugin. A hand-authored strict Remote descriptor connects its client to a host endpoint; the host reads one configured synthetic student's current calendar revision and proposal from the local domain service. The host exposes only `calendarSpike/view`; it provides no approval, calendar write or workspace tool. The component shows a stale notice if the proposal's context, evidence or calendar versions no longer match. It consumes the shared consumer's single-create `sections.near.action` proposal, rejects unsupported proposal/event semantics, filters cancelled tombstones, visibly labels tentative/transparent events, and displays a notice that it only shows same-day timed events, omits events starting and ending in the same minute, and that overlaps may cover one another. A time axis and event time ranges use São Paulo time; very short events may be enlarged or shifted to fit labels, as disclosed in the panel. Empty space is not a confirmation of availability; separate free/busy intervals are not drawn.

## Reproduce the programmatic carrier check

This branch requires the domain service/store and DSH dependencies from the domain-service draft. Use Node 24 and esbuild 0.25.5 in a dedicated temporary build environment:

```sh
npm install --prefix /tmp/study-panel-build esbuild@0.25.5 --no-audit --no-fund
ESBUILD_BIN=/tmp/study-panel-build/node_modules/.bin/esbuild node experiments/dsh-native-panel/build.mjs
node --test --test-isolation=none experiments/dsh-native-panel/{host,client-entry,panel-view,process-cleanup}.test.mjs
node experiments/dsh-native-panel/carrier-test.mjs
```

The test creates an isolated temporary DSH home, starts the domain service and DSH Web bound to `127.0.0.1`, seeds fictional records, and terminates both services. It uses a temporary, newly generated DSH web token solely in the test process to obtain a session cookie; neither is printed or persisted outside that temporary home. It sends no model requests and reads no user credentials. A hard-killed test could leave child processes or temporary files; inspect them before reusing the environment.

On 2026-11-07 the equivalent test passed: the actual DSH authenticated index included the plugin boot row; the built client bundle was served; an authenticated HTTP Remote call returned the synthetic calendar and proposal; a changed context surfaced a stale flag; unauthenticated calls returned 401; and unexported read/approval methods returned 404. Twenty-two unit checks also cover revision and record validation, the shared proposal format and actual planner event, ownership and IDs, cancellation/recurrence semantics, fixture timestamp placement, explicit-offset conversion, visible time ranges, bilingual existing/proposed legend and accessibility labels for short blocks, bilingual availability notices, fixed-week/calendar identity, malformed events, unsupported schemas, and confirmed child exit with bounded SIGTERM/SIGKILL escalation. The panel explicitly labels the view as a point-in-time snapshot. A non-stale result is a point-in-time revision comparison, not approval, availability or authorization to write; it does not refresh automatically. A subsequent isolated desktop browser check mounted the actual sidebar and displayed the synthetic class and proposed study block without a model request. This exposed and fixed a missing scoped remote-service injection and dark-host contrast. The registration-order check is automated; mounting and rendering were checked manually and are not covered by CI.

## Limits

- The desktop browser check covers mounting and display of one existing and one proposed synthetic event only. The narrow panel has small calendar labels, requires scrolling, and has not received responsive or comprehensive accessibility review. Reload/recovery, error and stale rendering, Portuguese browser behavior and review interactions remain unverified in the browser.
- The descriptor is hand-authored against DSH 0.2.2-rc.1; the pinned Typert generator is publicly available, but its standalone source-workspace build was not established. The result schema covers outer fields; nested proposal/calendar payloads remain generic.
- The domain service has no authentication. DSH web authentication is not a substitute for isolating the service from agent Bash or arbitrary local processes. The host and its plugin run with host authority; the agent sandbox and trusted review/write service are not wired here. Synthetic data only.
- The panel currently targets Ana and the fixed week 2–8 November 2026. Observation metadata must identify the fixed São Paulo week and matching calendar; explicit-offset timestamps are converted to São Paulo. Valid all-day/multiday and same-minute events are omitted and overlapping events can cover each other; the UI displays this limitation. Expanded recurring instances are shown individually; unexpanded series masters are rejected. It has no question, revision, approval, write, live refresh, recovery or partial-state UI.
- This is not a matched user-workflow comparison with the SDK app and does not justify selecting a shell. The future comparison must use the same domain records, rendering rules, questions, revision/review, stale/partial states and bilingual workflows in both implementations.
